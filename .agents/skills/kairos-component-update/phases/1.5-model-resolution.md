## Phase 1.5: Resolve the model pins

PHASE_KEY: q4vn7xtd
(Proof-of-load: `resolve-models.sh` refuses to run without `PHASE_KEY=q4vn7xtd` in its environment. The key is stated only in this file — never copy it into SKILL.md or another phase.)

Resolve the three tier pins for this run. **You do not pick models by judgment — `scripts/resolve-models.sh` does.** Full rationale for how it decides (the asymmetric capability-vs-cost rule, the frugal/balanced/thorough budget postures, the strong-tier ceiling, the `~/.kairos/models.yaml` answers-vs-resolutions model) lives in `reference/model-resolution.md`.

**Ordering is load-bearing: this phase runs after Phase 1 pre-flight and before Phase 2.** Pre-flight's fresh-mode sweep deletes `$RUN`, so a `model.txt` written any earlier goes with it — and the first dispatch is refused outright without one (mechanics: SKILL.md → Spawn accounting), so a skipped resolution stops the run rather than silently running it on the session model.

### 1. Resolve

1. Copy the offered-model list **verbatim from your tool surface** (never from memory), one slug per line, into `OFFERED`.
2. Run the script with `BUDGET` (default `balanced`, **never persisted**), `RUN`, and any `--*-model` overrides mapped to `STRONG_MODEL` / `CODER_MODEL` / `EXECUTOR_MODEL` (`--executor-model` / `--coder-model` / `--strong-model`, plus the `KAIROS_UPDATE_STRONG_MODEL` / `KAIROS_UPDATE_CODER_MODEL` / `KAIROS_UPDATE_EXECUTOR_MODEL` env equivalents the script reads itself — flag beats env, env beats derivation):

```bash
RUN=.kairos/migration/state; ctx() { sed -n "s/^$1=//p" "$RUN/context.env" | tail -1 | grep . || echo "FAIL: $1 missing from $RUN/context.env" >&2; }
SKILL_DIR=$(ctx SKILL_DIR)
OFFERED="<one slug per line, verbatim>" BUDGET="<the --budget value, else balanced>" RUN=$RUN PHASE_KEY=q4vn7xtd \
  "$SKILL_DIR/scripts/resolve-models.sh"
```

Then:

- **Check the exit status before reading anything** (see the branch table below).
- Read the four pins from `$RUN/model.txt`: `strong=<slug>`, `coder=<slug>`, `executor=<slug>`, `budget=<posture>`. All four are always present and non-empty on exit 0 — an empty pin is a refusal, never an output.
- Pins do **not** go into `.kairos/manifest.yaml` — they are strictly per-run (see `reference/model-resolution.md` for why).

### 1b. Non-zero exit — stop the phase, never carry it forward

A non-zero exit means this run has **no pins** — do not proceed to Phase 2, do not dispatch, and never hand-write pins: the run's first dispatch is refused without the file (SKILL.md → Spawn accounting), so an ignored failure resurfaces much later, after work has already run on an unpinned model. Whether a `$RUN/model.txt` still on disk is trustworthy depends on *which* failure you got — four cases, one rule each:

- **Normally: nothing survives.** The script removes `$RUN/model.txt` whenever it can, a stale one from an earlier resolution included. No file, no ambiguity.
- **Two refusals leave a surviving file VALID** — the **phase-key refusal** (this file was not loaded) and a **`*_MODEL` override-shape refusal** (`ov_check`, which fires before `BUDGET`, the catalog or `OFFERED` are even read). Both exit *before* any resolution attempt starts, so neither has pins of its own to void: an existing `$RUN/model.txt` predates the check and is still this run's truth. Do **not** treat it as stale and do **not** hand-delete it. (Section 3's mid-run correction relies on this — it re-feeds the run's own surviving pins back as overrides, and a shape refusal on one tier must not void the other two.)
- **Read-only `$RUN`: any survivor is STALE, both ways it can happen.** Either removal of a stale file failed (a `WARNING:` names the files left behind) or a *successful* resolution had nowhere to install its pins (exit **1** naming the directory, never exit 0). Either way the `model.txt` on disk is a superseded run's: fix the permissions or delete it by hand, and never dispatch against it. (Why a permissions problem never masquerades as an ordinary exit-1 resolution failure — the up-front writability probe and the temp outside `$RUN` — is in `scripts/resolve-models.sh`'s header.)

**Exit 1 — the invocation or the environment, never the answers file.** Each cause names itself on stderr; fix that one and re-run:

- **`OFFERED` empty, or unset on an interactive stdin** — re-copy the offered list verbatim from your tool surface, **one slug per real newline**: a mid-line CR means the paste used CR-only line endings and arrived as one line; a trailing CR is trimmed and fine; collapse a doubled space in a display name to one.
- **an `OFFERED` slug carrying a control byte, or a run of two-plus interior spaces** — stderr quotes the offending line; re-copy it clean.
- **bad `BUDGET`, or a catalog not found / carrying an invalid family rank** — fix `BUDGET` / `CATALOG`.
- **a `*_MODEL` override that is not slug-shaped** (stderr names the variable) — trimmed of surrounding whitespace and a trailing CR, the value must be non-empty and use only letters, digits and `. _ - : /`; an offered *display name with single spaces* can be derived but cannot be passed as an override.
- **`$RUN` not writable** (stderr names the directory) — fix its permissions; the pins resolved but had nowhere to install.
- **the `FAIL: load phases/…` guard** — this file was not loaded; load it and re-run.

### 2. Surface the pins — immediately, not at the first spawn

**Immediately after reading the pins** — the user must see them while there is still time to say "use X instead" before any subagent runs — surface the defaults in one non-blocking line, e.g. "conflict resolution and flagged-task verification on `<slug>`; flagged/bootstrapped implementation on `<slug>`; routine implementation and verification on `<slug>` — say so to change; name included plan models and routine work moves to the strongest included."

Fold in whatever the script emitted on stderr, handled at this same moment:

- `UNCLASSIFIED:` / `UNRANKED:` — you MAY research and *propose* a user-confirmed `capability_overrides` entry, and suggest a PR to `reference/model-families.yaml`.
- `WARNING:` — surface as-is.
- `CHOICE:` — a `frugal`-budget same-rank pin question; ask it with the script's pick as the default.
- On first run, if `~/.kairos/models.yaml` has no `plan_confirmed` stamp — state the IFS-plan assumption, then stamp `plan_confirmed`.
- Premium session model — add one extra line: only orchestration/planning use it; subagents do not inherit.

Safety net: if this session has not surfaced that line (e.g. a resumed run whose pins were resolved in an earlier session), surface it once before the run's first dispatch (Phase 5 or 7).

### 3. Mid-run correction

If the user corrects a pin later in the run, **do not just re-run `scripts/resolve-models.sh` bare.** It re-derives all three tiers from `BUDGET` on every invocation, so a bare re-run silently redraws the tiers the user did *not* ask to change — exactly the mid-plan switch `reference/continue.md` → *Re-read the pinned models, don't re-derive them* exists to prevent (a frugal run re-run with `BUDGET` left to default flips `coder=` and `budget=` away from the posture this run resolved).

Instead, read the run's posture and surviving tiers off `$RUN/model.txt`, then re-resolve feeding back **only** what should not move:

- **Always pass `BUDGET` back** — it is never persisted, so a bare re-run defaults it to `balanced`.
- **Feed each uncorrected tier back as an explicit override** — an override beats every derivation, so this pins it against the re-derivation — **except a `coder=` pin the frugal collapse produced.** Passing a collapse-produced pin back strands coder on the superseded slug while the corrected executor moves; blanking a *user-pinned* coder silently discards a choice the user made. Same class of loss, opposite directions — so you must know which kind of `coder=` you hold.

**Which kind of `coder=` is it?** Both spell the same `coder=<slug>` line, so `$RUN/model.txt` cannot tell you. Decide `CODER_FROM_COLLAPSE` from the run's **own invocation** (the flags/env Phase 1's argument extraction recorded), first match wins:

- Coder is itself the tier being corrected now → **`no`** (pinning it is then the correction).
- The run carried `--coder-model` or a standing `KAIROS_UPDATE_CODER_MODEL` → **`no`** — that pin is the user's, even under frugal.
- `budget=frugal` and no coder override on the invocation → **`yes`** — the collapse copied `executor=` into `coder=`, and the pin must follow the corrected executor.
- The invocation record is genuinely gone (a resume after compaction) → **ask the user; `no` is the safe default** — a stranded tier is re-correctable, a discarded pin is not.

**A surviving pin that is a display name with spaces cannot be passed back as an override** (same constraint as the exit-1 table row above: `resolve-models.sh`'s override shape gate accepts only `A-Za-z0-9._:/-`, so a display name can be *derived* but not *overridden*). Omit that tier's value — empty and unset read the same at the script's flag layer (its override gate is `[ -n ]`-guarded, and the invocation below passes `${VAR:-}` for exactly this reason), so the flag layer falls through to `KAIROS_UPDATE_*_MODEL` / derivation exactly as for a tier that was never overridden. Because `OFFERED` is passed back verbatim below, an omitted tier re-ranks against the same catalog + `OFFERED` that produced it and lands on the identical slug — nothing is lost. (`resolve-models.sh` never wipes a *valid* `$RUN/model.txt` over a rejected override — an override-shape refusal exits before any resolution attempt starts — but omitting the spaced pin means you never trigger that refusal at all.)

```bash
RUN=.kairos/migration/state; ctx() { sed -n "s/^$1=//p" "$RUN/context.env" | tail -1 | grep . || echo "FAIL: $1 missing from $RUN/context.env" >&2; }
SKILL_DIR=$(ctx SKILL_DIR)
BUDGET=$(sed -n 's/^budget=//p' "$RUN/model.txt")
STRONG_MODEL=$(sed -n 's/^strong=//p' "$RUN/model.txt")
CODER_MODEL=$(sed -n 's/^coder=//p' "$RUN/model.txt")
EXECUTOR_MODEL=$(sed -n 's/^executor=//p' "$RUN/model.txt")
# A pin outside the override shape (anything but A-Za-z0-9._:/-) can only be a
# display-name slug derived from OFFERED, never something resolve-models.sh
# itself wrote as an override — blank it (empty reads as absent at the script's
# flag layer) so it re-derives instead of being rejected by the shape gate.
# Spelled per variable, never as a `${!var}` indirection loop: this block runs in
# the harness's tool shell, which may be zsh, where `${!var}` is a fatal `bad
# substitution` that kills the whole block before the re-resolution runs.
case "$STRONG_MODEL"   in *[!A-Za-z0-9._:/-]*) STRONG_MODEL="" ;; esac
case "$CODER_MODEL"    in *[!A-Za-z0-9._:/-]*) CODER_MODEL="" ;; esac
case "$EXECUTOR_MODEL" in *[!A-Za-z0-9._:/-]*) EXECUTOR_MODEL="" ;; esac
# Now overwrite ONLY the corrected tier's variable with the user's new slug,
# e.g. EXECUTOR_MODEL="<the corrected slug>" — leave the others as read above
# (or blanked by the shape guard just above).
# Then set this from the run's OWN invocation, never from model.txt — the
# decision list above ("Which kind of coder= is it?") is the rule, arm by arm.
CODER_FROM_COLLAPSE="<yes|no>"
if [ "$BUDGET" = frugal ] && [ "$CODER_FROM_COLLAPSE" = yes ]; then CODER_MODEL=""; fi
OFFERED="<one slug per line, verbatim>" BUDGET="$BUDGET" \
  STRONG_MODEL="${STRONG_MODEL:-}" CODER_MODEL="${CODER_MODEL:-}" EXECUTOR_MODEL="${EXECUTOR_MODEL:-}" \
  RUN=$RUN PHASE_KEY=q4vn7xtd "$SKILL_DIR/scripts/resolve-models.sh"
```

An empty `CODER_MODEL` is treated as unset **at the flag layer only**, which is exactly why blanking it is not the same as carrying no coder override: `resolve-models.sh` then refills the empty flag from `KAIROS_UPDATE_CODER_MODEL`, because standing configuration beating a derivation is by design. So under a standing env pin the blanking above changes nothing, and the pin re-appears as an override. Under `balanced` and `thorough` no tier is collapse-derived, so all three pins go back verbatim and only the corrected one moves.

The stderr lines are the check, read against the case you are in. **Coder follows the new executor unless it is pinned by flag or by standing env.** With no coder pin, `coder=` must read `[frugal: <CODER_MODEL> collapses into <EXECUTOR_MODEL>]` on the new slug — an `[explicit override]` there means a collapse-produced pin was passed back and coder is stranded on the superseded model. With coder pinned, `coder=` reads `[explicit override — beats every derivation]` on the pinned slug and that is **correct**, not the stranding above: the pin is doing its job, so do not "fix" it by blanking the variable.

When the correction should persist beyond this run, write `cost_overrides` / `capability_overrides` / `plan_confirmed` to `~/.kairos/models.yaml` before the call above. Either way, the call rewrites `$RUN/model.txt` in place — note the correction in `.kairos/migration-log.md`.

The pins are enforced from here on: `log-spawn.sh` refuses to record a dispatch whose requested model is not the pin for its declared tier, so a corrected pin must be a re-resolution, never a hand-typed slug on the next dispatch (SKILL.md → Spawn accounting).

### Exit

`$RUN/model.txt` exists with all four lines, and the pins have been surfaced. Proceed to Phase 2.
