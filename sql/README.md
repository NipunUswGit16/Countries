# SQL Migrations

This directory contains auto-generated PostgreSQL SQL migration files created by `kairos-gen`.

## What's Generated

For each entity in your codebase that embeds `EntityBase[T]` or `MasterDataEntityBase[T]`, a corresponding SQL file is automatically generated with:

- `CREATE TABLE IF NOT EXISTS` statements
- Proper column types (id + JSONB data column)
- GIN indexes for efficient JSONB queries
- Custom columns and indexes (via directives)

## File Naming

SQL files are named after the entity (in snake_case, pluralized):
- `Order` → `orders.sql`
- `CustomerProfile` → `customer_profiles.sql`
- `ProductEntityV1` → `product_entities.sql` (version suffix removed)

## Generation

Files are automatically generated by running:

```bash
make generate
```

This is also run automatically:
- On `make build-all`
- Before each `git push` when the pre-push hook is installed (`make install-hooks`)
- In CI/CD pipelines

## Customization

To customize the generated SQL, use `+kairos:sql:` directives in your entity definitions:

```go
// +kairos:sql:table:custom_orders
// +kairos:sql:column:created_at TIMESTAMP NOT NULL DEFAULT NOW()
// +kairos:sql:index:idx_orders_customer BTREE ((data->>'customerId'))
type Order struct {
    entities.EntityBase[entities.EntityId] `json:",inline"`
    CustomerName string `json:"customerName"`
    TotalAmount  float64 `json:"totalAmount"`
}
```

Expression indexes need double parentheses (`BTREE ((data->>'x'))`); use `BTREE`, not `GIN`, for a `->>` expression because `text` has no default GIN operator class.

### SQL directives (`+kairos:sql:*`)

| Directive | Effect |
|---|---|
| `+kairos:sql:table:<name>` | Override table name (defaults to snake_case plural of struct name) |
| `+kairos:sql:column:<definition>` | Add a custom column (valid PostgreSQL column definition); repeatable |
| `+kairos:sql:index:<name> [UNIQUE] GIN\|BTREE <def> [WHERE <pred>]` | Add a custom index (optional UNIQUE, optional partial WHERE) |
| `+kairos:sql:index:no-auto-gin-index` | Disable the default GIN index on the `data` column |
| `+kairos:sql:index:auto-gin-index-operator:<class>` | Override the operator class for the default GIN index (e.g. `jsonb_path_ops`) |
| `+kairos:sql:idtype:<type>` | Override the `id` column type (defaults to `UUID`) |
| `+kairos:sql:ignore` | Skip SQL generation for this entity |
| `+kairos:sql:lib:<modulePath>` | Copy SQL files from an external Go module's `sql/` directory into `sql/0.libs/` |
| `+kairos:sql:loader:disable` | Skip loader generation for this entity |
| `+kairos:sql:loader:column-sql:<col>:<expr>` | Provide the SQL expression for a custom column in the loader (supports `{PropertyName}` placeholders) |

`UNIQUE` requires `BTREE` (PostgreSQL GIN does not support unique indexes; `UNIQUE` + `GIN` is a generate-time error). `WHERE` works with either index type and composes with `UNIQUE` for a partial unique index. Both keywords are case-insensitive and normalized to uppercase in the emitted SQL; emission stays idempotent (`IF NOT EXISTS`). A single expression column must be double-parenthesized (`((expr))`) — single parens are for a column list:

```go
// Partial unique index — one active email, soft-deletes ignored
// +kairos:sql:index:uq_active_email UNIQUE BTREE ((data->>'email')) WHERE data->>'deletedAt' IS NULL

// COALESCE unique — NULLs participate in uniqueness
// +kairos:sql:index:uq_code UNIQUE BTREE ((COALESCE(data->>'code','')))

// Case-insensitive expression index
// +kairos:sql:index:idx_name_ci BTREE ((lower(data->>'name')))
```

### Master-data directives (`+kairos:masterdata:*`)

Applied to structs embedding `entities.MasterDataEntityBase[T]`.

| Directive | Effect |
|---|---|
| `+kairos:masterdata:no-cdc` | Exclude entity from the CDC descriptor and suppress `REPLICA IDENTITY FULL` on its table |
| `+kairos:masterdata:table:<name>` | Backward-compatible alias for `+kairos:sql:table:<name>` |

### Schema validation directives (`+kairos:schema:*`)

Applied to **struct fields** to add JSON Schema validation constraints. These affect `pkg/json-schema/` (and AsyncAPI payloads) from `make generate`, not the SQL.

Every directive maps to a standard JSON Schema draft-07 keyword. The set mirrors the keywords harvested swag struct tags can produce (below) so a directive can override **any** tag-derived key — the Kairos directive always wins.

| Directive | Effect |
|---|---|
| `+kairos:schema:required` | Mark the field as required (see requiredness / precedence below) |
| `+kairos:schema:minimum=<n>` | Minimum value for numeric fields |
| `+kairos:schema:maximum=<n>` | Maximum value for numeric fields |
| `+kairos:schema:exclusiveMinimum=<n>` | Exclusive minimum for numbers |
| `+kairos:schema:exclusiveMaximum=<n>` | Exclusive maximum for numbers |
| `+kairos:schema:multipleOf=<n>` | Value must be a multiple of |
| `+kairos:schema:minLength=<n>` | Minimum string length |
| `+kairos:schema:maxLength=<n>` | Maximum string length |
| `+kairos:schema:minItems=<n>` | Minimum items for arrays |
| `+kairos:schema:maxItems=<n>` | Maximum items for arrays |
| `+kairos:schema:uniqueItems=true` | Require unique array items |
| `+kairos:schema:pattern=<regex>` | Regex pattern for string validation |
| `+kairos:schema:format=<format>` | Format hint (e.g. `email`, `date-time`) |
| `+kairos:schema:enum=<v1>,<v2>,...` | Restrict to a fixed set of values (typed to the field) |
| `+kairos:schema:examples=<v1>,...` | Draft-07 `examples` array (typed); never singular `example` |
| `+kairos:schema:default=<value>` | Default value for the field |

### Swag struct tags (dual annotation)

`kairos-gen` also harvests a swaggo/swag-compatible subset of struct tags into the same draft-07 keywords, so structs annotated for Swagger get faithful messaging schemas without duplicating every constraint as a directive. Route comment annotations (`@Param`, `@Success`, …) are **not** consulted.

| Struct tag | JSON Schema key(s) | Notes |
|---|---|---|
| `validate:"required"` / `binding:"required"` | `required` | Explicit required |
| `validate:"optional"` / `binding:"optional"` | (not required) | Explicit opt-out |
| `validate:"min=N"` / `max=N` | numeric → `minimum`/`maximum`; string → `minLength`/`maxLength`; array → `minItems`/`maxItems` | Type-routed |
| `validate:"gte=N"` / `lte=N` | `minimum` / `maximum` | Numeric |
| `validate:"gt=N"` / `lt=N` | `exclusiveMinimum` / `exclusiveMaximum` | Numeric |
| `validate:"len=N"` | string → `minLength`+`maxLength`; array → `minItems`+`maxItems` | Exact bound |
| `validate:"unique"` | `uniqueItems: true` | Arrays |
| `validate:"oneof=a b c"` | `enum` (typed) | Space-separated |
| `enums:"a,b,c"` | `enum` (typed) | Comma-separated |
| `format:"email"` | `format` | |
| `default:"…"` | `default` (typed) | |
| `example:"…"` | `examples` (one-element array) | Never singular `example` |
| `swaggertype:"string"` / `"integer,int64"` | `type` (+ `format`) | Overrides inferred type |
| `swaggerignore:"true"` | field omitted | Like `json:"-"` |

**Preferred authoring style (when `internal/integration-api/openapi.go` exists — same signal as toolkit `HAS_OPENAPI`):** swag struct tags. Use `+kairos:schema:*` only as an escape hatch (no tag maps to the keyword, or the messaging schema must diverge from Swagger). If that file is absent, use `+kairos:schema:*` directives only (legacy).

**Precedence (later wins per key):** Go type inference → swag tags → `+kairos:schema:*` (Kairos always final authority).

`make generate` passes `--swag-full-compat`, so requiredness is swag optional-by-default: a field is required only via `+kairos:schema:required` or a `validate`/`binding` `"required"` token. Full tables and the worked example live in the [kairos-gen README](https://bitbucket.org/ifs-pd/kairos-component-common/src/main/cmd/kairos-gen/README.md#kairos-schema-directives).

## Usage

### Automated Migration (Recommended)

Use the built-in `make` commands to automatically apply migrations:

```bash
# Run migrations with default tenant ID
make db-generate

# Run with custom tenant ID
make db-generate TENANT_ID=your-tenant-id

# Run with custom database connection
make db-generate DB_HOST=localhost DB_PORT=5432 DB_USER=postgres DB_PASSWORD=postgres

```

### Manual Application

These SQL files can also be:
- Applied manually using `psql`
- Integrated with migration tools (e.g., golang-migrate, Flyway)
- Deployed as part of your CI/CD pipeline

All generated statements use `IF NOT EXISTS` clauses, making them safe to run multiple times.

## Important

⚠️ **Do not manually edit these files** - they will be overwritten on the next `make generate` run. Use directives to customize instead.
